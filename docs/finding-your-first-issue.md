# Finding Your First Issue

Once you've done the practice PR in this repo, here's how to find a real
project to contribute to.

## Search for labeled issues

Most projects label issues that are safe for newcomers:

- `good first issue` — small, well-scoped, usually has enough context to start.
- `help wanted` — maintainers are actively looking for outside help.
- `beginner-friendly` / `starter` — less standardized, but common.

GitHub has a dedicated search for this:
https://github.com/topics/good-first-issue and
https://github.com/search?q=label%3A%22good+first+issue%22+state%3Aopen

## Signals a repo is a good place to start

Before picking an issue, check the repo itself:
- Has it had commits in the last few months? (Stale repos rarely respond to PRs.)
- Does it have a `CONTRIBUTING.md`? That means the maintainers expect and
  support outside contributors.
- Do open PRs get reviewed and merged, or do they sit for months? Check the
  "Pull requests" tab.
- Does it have a code of conduct? A small but useful signal about how
  newcomers are treated.

## Picking an issue that matches your level

- Read the whole issue description and any linked discussion before claiming it.
- If it's unclear, ask a clarifying question in the issue *before* starting
  work — better than building the wrong thing.
- Comment that you'd like to work on it so two people don't duplicate effort.
- Start smaller than you think you need to. A tiny, correct PR beats a huge,
  half-right one.
